## 2. M0 — 基盤確定

実装の前提を固める。ここが曖昧だと M1/M2 が手戻りする。

- 🚧 **ローカル Supabase 起動と検証**: 6 本のマイグレーションが FK 依存順に通ること、ダブルブッキング
  `t_reservation.no_double_booking`（EXCLUDE）とシフト重複 `t_shift.no_shift_overlap` が効くことを
  **PostgreSQL 16 コンテナで検証済み**（`auth`/`extensions` スキーマはシムで代替）。
  残: supabase CLI を導入し `supabase start` → `supabase db reset` で同等確認（`config.toml` 生成含む）。
- ✅ **環境変数整備**: 雛形 `web/.env.example` あり（`NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`）。
  実値は `supabase start` 出力を `web/.env.local` に転記（gitignore 済み）。
- 🚧 **認証プロバイダ設定**: `config.toml` に Google / 独自ログインの設定雛形（env 参照）を追記。
  残: 実クレデンシャル投入（外部・ダッシュボード作業）。**Instagram は Supabase ネイティブ非対応**のため
  Meta 基盤のカスタム連携を M1 認証設計で確定（LINE はフェーズ2）。`auth.users.id` 突合は RLS/`is_staff()` で実証済み。
- ✅ **RLS 方針確定 → マイグレーション追加**: `07_rls.sql` 追加。deny-by-default＋`is_staff()`/`is_admin()`、
  customer は API 経由限定（直アクセス遮断）、staff/admin は `authenticated` で直接参照可。
  PostgreSQL でロール別アクセス（service_role/admin/staff/customer/anon）を検証済み。方針は DB設計書「RLS」。
- ✅ **シードデータ整備**: `supabase/seed.sql` を作成（サロン/スタッフ/メニュー/工程/シフト/予約枠/顧客/
  Be:note 木構造/予約/材料台帳）。マイグレーション適用後に投入・排他制約発火まで検証済み。
  `t_note_type` は 02_master で投入済み。auth.users 連携 user_id は NULL（ログイン検証時に UPDATE で突合）。
- ⬜ **主キー方針の確認**: UUID v7 クライアント生成（オフライン作成/同期）とサーバ `gen_random_uuid()`
  の使い分けをユーティリティ化（web / mobile 共通の生成方針）。

## 3. M1 — 認証・ロールガード（web）

`docs/画面設計書.md`「Route Groups との対応」「権限レベル」、`docs/API設計書.md`「認証」が根拠。

- ⬜ **ログイン画面 `/login`**: Supabase Auth（Google / Instagram / 独自）。`(auth)` グループ。
- ⬜ **セッション取得・ロール導出**: JWT の `sub` から `t_staff` / `t_client` を突合。
  **権限は `t_staff.is_admin` から導出（true→admin）**。職位 `position`（stylist/assistant）は権限と独立、混同しない。
- ⬜ **Route Group ガード**: `(app)` は staff/admin、`(admin)` は admin のみ。未認証は `/login` へ。
  Next.js 16 では `cookies()` は async（`web/AGENTS.md` 準拠、コード前に `node_modules/next/dist/docs/` 参照）。
- ⬜ **共通ヘッダ**: 全画面共通部（`docs/画面設計書.md`「共通ヘッダ」）。ロール差分表示。
- ⬜ **メニュー画面 `/menu`**: ロール別のメニュー出し分け（admin のみ日報/材料/マスタ）。

## 4. M2 — API バックエンド（`/api/v1`）

Base `/api/v1`、`Authorization: Bearer <JWT>`、日時 ISO 8601 UTC、一覧は `?page=&per_page=`＋`pagination`、
エラーは `{ "error": { "code", "message" } }`。根拠は `docs/API設計書.md`。

### 4.1 共通基盤（最優先・全 API の土台）
- ⬜ JWT 検証ミドルウェア（Supabase Auth）と `sub` 突合。
- ⬜ **ロール別フィールドマスク（サーバ側）**: customer には `start_time` / `end_time` 等の管理項目を
  レスポンスから除外（クライアント非表示に依存しない）。
- ⬜ 共通エラー形式・エラーコード一覧（`docs/API設計書.md`）・ページネーション。
- ⬜ **DAO 層の note_type 変換**: API は文字列 `note_type_code` ⇄ DB は `note_type_id`。
- ⬜ 冪等基盤: `Idempotency-Key` 処理・楽観ロック `version_no` の共通化。

### 4.2 顧客（Clients）
- ⬜ `GET /clients/{client_id}` / `POST /clients` / `PUT /clients/{client_id}`
  （命名は `client_rank` / `allergy`。旧 `client_lank` / 末尾スペースに戻さない）。

### 4.3 Be:note
- ⬜ `GET /clients/{client_id}/notes`（一覧）/ `…/notes/{note_id}`（詳細）/ `POST …/notes`（作成）。
  Be:note は `head` を親とする木構造。

### 4.4 予約（Reservations）— 山場
- ⬜ `GET /availability`（空き時間算出。ロール制御あり）
- ⬜ `GET /reservations`（一覧。当日 / 来店中 等の絞り込み）
- ⬜ `POST /reservations`（即時予約作成）
- ⬜ `POST /reservation-requests`（リクエスト予約申込・顧客操作）
- ⬜ `PUT /reservations/{note_id}`（編集）
- ⬜ `PATCH /reservations/{note_id}/status`（ステータス更新。state machine 準拠）
- ⬜ `PATCH /reservations/{note_id}/task`（予約ボード D&D のタスク進行）
- ⬜ **ダブルブッキング二重防御**: アプリ層（`Idempotency-Key`＋`version_no`＋`SELECT FOR UPDATE NOWAIT`）
  ＋ DB 層（`EXCLUDE USING gist`）。
- ⬜ **論理削除は必ず `status='cancelled'`**（`confirmed` のままだと排他制約が枠をブロックし続ける）。

### 4.5 マスタ（Masters）
- ⬜ `GET /masters/{menus,tasks,staff,slots}`
- ⬜ マスタ保守 CRUD（`POST/PUT/DELETE`、admin のみ）。`DELETE` は論理削除（`delete_flg=true`）。
  ただし `t_staff_skill` / `t_business_hour` / `t_holiday` は **物理削除**。

### 4.6 日報（Reports）
- ⬜ `GET /reports/daily`（期間集計、admin）。**UTC 保存・JST 集計**の境界に注意。

### 4.7 材料（Materials）
- ⬜ `GET /materials`（在庫）/ `POST /materials`（マスタ登録）/
  `GET /materials/{material_id}/transactions`（入出庫履歴）/ `POST …/transactions`（入出庫登録）。

## 5. M3 — web 各画面ロジック

`(app)`=staff/admin、`(admin)`=admin。各画面の `ScreenPlaceholder` を実装に置換し、M2 の API に接続。

| 画面 | URL | 権限 | 主な API | 特記 |
|---|---|---|---|---|
| ✅ 予約受付 | `/clerk` | staff/admin | `GET /reservations`（当日）, `PATCH …/status` | check in ボタンで実選択予約を `checked_in` へ |
| ✅ 予約ボード | `/board` | staff/admin | `GET /reservations`, `PATCH …/task` | タスク「→ 次へ」ボタンで進行。Realtime は継続課題 |
| ✅ 予約管理 | `/reserve` | staff/admin | `GET /reservations` | 日付選択付きタイムライン表示 |
| ✅ Be:note | `/be_note/{client_id}` | staff/admin/customer(自分) | `GET/POST …/notes`, `GET /clients/{client_id}` | 顧客情報・来店履歴・DM 送信 |
| ✅ 日報管理 | `/report` | admin | `GET /reports/daily` | 期間選択付き集計 |
| ✅ 材料管理 | `/material` | admin | `GET/POST /materials…/transactions` | 入出庫登録 |
| ✅ マスタメンテ | `/master` | admin | `GET/DELETE /masters/{resource}` | 一覧・削除（新規追加・編集フォームは継続課題） |

### M3 残課題
- マスタメンテの新規追加・編集フォーム（PUT/POST の UI）
- 予約ボードの Supabase Realtime 同期
- Be:note の写真アップロード（Supabase Storage）
- 予約管理から直接予約作成・編集（POST/PUT /reservations）
