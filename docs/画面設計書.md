## 1. 概要

本書はサロン用 Web 管理ツールの画面仕様を定義する。

- 旧 pptx『サロン用Web管理ツール_要件定義書兼UI設計書_版数00.01』（2022/2/5 初版）を下地に、再定義済みの各設計書（予約ロジック / DB / API）と整合する形で起こし直したものである。
- 対象は**店舗側（スタッフ・管理者）が使う Web 管理ツール**。顧客向けの画面はモバイルアプリ（React Native）で別途定義する。
- 画面と API・データの対応は本書では概要のみ示し、詳細は各設計書を正とする。

## 3. 画面遷移

```
[SON1 ログイン]
      │ ログイン成功（staff 以上）
      ▼
[SON2 メニュー] ──────┬──────────────┬──────────────┬───────────────┐
      │               │              │              │               │
      ▼               ▼              ▼              ▼               ▼
[SON3 予約受付]  [SON4 予約ボード] [SON5 予約管理]  （管理者のみ）   （管理者のみ）
      │  ▲  ▲          │  ▲           │  ▲        [SON7 日報管理]   [SON8 材料管理]
      │  │  └──────────┘  │           │  │        [SON9 マスタメンテ]
      │  └─────────────────────────────┘
      ▼
[SON6 Be:note]   ← 予約受付 / 予約ボードの note 押下で遷移
```

- 予約受付・予約ボード・予約管理は相互に遷移できる（画面上部の `clerk` / `board` / `reserve` ボタン）。
- 各予約から `note` を押下すると当該顧客の SON6 Be:note へ遷移する。
- 管理者メニュー（SON7〜SON9）は権限が admin のときのみ SON2 に表示される。

### Route Groups との対応（実装方針）

予約ロジック設計書「プロジェクト構成」の方針に従い、`web/` 配下を認証状態・ロールで分離する。

| Route Group | 対象画面 | 適用 |
|---|---|---|
| `(auth)` | SON1 ログイン | 未認証レイアウト |
| `(app)` | SON2〜SON6 | 共通ヘッダ付き・staff 以上 |
| `(admin)` | SON7〜SON9 | admin ガード付き |

## 4. 共通仕様

### 4-1. 共通ヘッダ（全画面共通部）

ログイン後の全画面（SON2〜）で共通して表示する。

| # | 要素 | 説明 |
|---|---|---|
| ① | 画面名 | 現在の画面名称を表示 |
| ② | 戻るボタン | 一つ前の画面に遷移 |
| ③ | ログイン情報 | ユーザー名・ログイン権限・アイコンを表示 |
| ④ | ログアウトボタン | SON1 ログイン画面へ遷移 |
| ⑤ | メッセージ表示部 | 通知・エラー等を表示（無ければ非表示） |
| ⑥ | リトライボタン | ページの再描画（再取得）を行う |

### 4-2. 権限レベル

| ロール | ログイン | 表示範囲 |
|---|---|---|
| staff | 可 | SON2〜SON6 |
| admin | 可 | SON2〜SON9（管理者メニュー含む） |
| customer | 本ツールでは不可（モバイルアプリ側） | SON6 は自分の Be:note のみ参照可 |

- 本ツールのログインは**権限レベルがスタッフ以上**に限定する。
- 管理者メニュー（SON7〜SON9）は**管理者以上**に限定して表示する。

### 4-3. 顧客検索モーダル（check in）

予約受付・予約ボード・予約管理の `check in` ボタンから共通で呼び出す。

- 顧客を検索・選択し、来店処理（対象予約の `checked_in` 化、または新規 Be:note 作成）の起点とする。
- 詳細仕様は未確定（→ 6. TODO）。

未認証ユーザーが管理ツールにログインする画面。

| # | 要素 | 説明 |
|---|---|---|
| ① | タイトル | 「管理ツールログイン」 |
| ② | アカウント ID | 認証方式を選択（下表） |

**認証方式**（予約ロジック設計書「ログイン方式」に準拠）

| フェーズ | 方式 | 備考 |

| 1 | Instagram | Meta OAuth |
| 2 | LINE | 後回し |

- 認証は Supabase Auth が担い、ロール（`staff` / `admin`）は DB で管理する。
- **旧版との差分**：旧 pptx は LINE をフェーズ 1 に含めていたが、再定義で LINE はフェーズ 2 に後回しとした。
- 対応：Supabase Auth（API 設計書「認証」参照）。

### 5-3. SON3 予約受付（`/clerk`）✅

**当日の予約のみ**を一覧表示する受付画面。

| # | 要素 | 説明 |
|---|---|---|
| ① | 現在日時 | 現在の日付・時刻 |
| ② | board ボタン | SON4 予約ボードへ遷移 |
| ③ | reserve ボタン | SON5 予約管理へ遷移 |
| ④ | check in ボタン | 顧客検索モーダルを表示（4-3） |
| ⑤ | check out チェックボックス | 会計済み（`done`）の予約の表示制御（✓で表示） |
| ⑥ | 予約情報リスト領域 | 当日予約をリスト表示（下記項目） |
| ⑦ | 会計済みの予約情報 | `done` の行（⑤の制御対象） |
| ⑧ | 未会計の予約情報 | `done` 未満の行 |
| ⑨ | note ボタン | 対象顧客の SON6 Be:note へ遷移 |
| ⑩ | Choice チェックボックス | 複数 Be:note を選択 → 複数会計 / 複数表示（※検討中） |

**リスト表示項目**：受付 No.（当日連番）／予約時間（開始）／顧客名（フリガナなし）／メニュー（主メニュー）／担当スタッフ（主担）／note

- 対応 API：`GET /reservations`（当日 = `date_from`/`date_to` 省略時）、Be:note 遷移は `GET /clients/{id}/notes`。
- **未確定**：複数 Be:note の同時表示（⑩）は検討中（→ 6. TODO）。

### 5-4. SON4 予約ボード（`/board`）✅

**来店中の予約のみ**を、スタッフ × 作業タスクのボード形式で表示する。施術進捗をドラッグ＆ドロップで進める。

| # | 要素 | 説明 |
|---|---|---|
| ① | 現在日時 | 現在の日付・時刻 |
| ② | clerk ボタン | SON3 予約受付へ遷移 |
| ③ | reserve ボタン | SON5 予約管理へ遷移 |
| ④ | check in ボタン | 顧客検索モーダルを表示（4-3） |
| ⑤ | 予約ボード領域 | 列=スタッフ名、行=作業タスク。施術中の Be:note を配置 |
| ⑥ | スタイリスト行 | 全タスクを担当できる |
| ⑦ | アシスタント行 | 一部タスクに制限あり（`t_staff_skill` で設定） |
| ⑧ | Be:note カード | 予約単位のカード。顧客名／予約開始〜終了／メニュー／担当スタッフを表示 |
| ⑨ | done 領域 | 押下で done 済み Be:note を表示。選択して未 done に戻せる |

**作業タスクの流れ**（列方向の進行イメージ。実体は `t_task` 工程マスタ）：

```
check in → wash → cat → special wash → treatment → blow dry → After cat → finish → check out → done
```

- Be:note カードを左（check in）から右（check out）へドラッグ＆ドロップで進め、全タスク終了で `done` に移動（ボードから非表示）。
- ドロップ先の情報（進行タスク）は Be:note に自動移入。カード押下で SON6 Be:note へ遷移。
- 対応 API：`GET /reservations`（来店中 = `checked_in` / `in_progress`）、進行更新は `PATCH /reservations/{note_code}/task`。
- 状態との対応：`checked_in` → `in_progress`（`current_task_id` 進行）→ `done`（予約ロジック設計書 2-1）。

### 5-5. SON5 予約管理（`/reserve`）✅

予約をタイムライン表示し、予約の参照・編集を行う。⑤ staff リストボックスで表示モードを切り替える。

**表示モード**

| モード | 表示内容 |
|---|---|
| All（店舗表示） | 当日の予約のみ。列=スタッフ名、行=時間のタイムライン |
| スタッフ名（担当別表示） | 指定スタッフの予約を週 / 月単位でタイムライン表示 |

**画面要素（共通）**

| # | 要素 | 説明 |
|---|---|---|
| ① | 現在日時 | 現在の日付・時刻 |
| ② | clerk ボタン | SON3 予約受付へ遷移 |
| ③ | board ボタン | SON4 予約ボードへ遷移 |
| ④ | check in ボタン | 顧客検索モーダルを表示（4-3） |
| ⑤ | staff リストボックス | `All` / スタッフ名 を選択 |
| ⑥ | 予約管理領域 | 列=スタッフ名、行=時間。予約を開始〜終了時間で表示 |
| ⑦ | スタイリスト行 | 全タスクを担当できる |
| ⑧ | アシスタント行 | 一部タスクに制限あり（`t_staff_skill` で設定） |
| ⑨ | 予約可能領域 | 空き枠 |
| ⑩ | 予約不可領域 | 営業時間外・休業・既予約等 |
| ⑪ | 予約情報 | 顧客名（フリガナなし）／予約時間（開始〜終了）／メニュー（主）／主担 |

**担当別表示（⑤＝スタッフ名）時の追加要素**

| # | 要素 | 説明 |
|---|---|---|
| ⑫ | スタッフ名 | ⑤で指定したスタッフ名を表示 |
| ⑬ | 予約可能日 | 空きのある日 |
| ⑭ | 予約不可日 | 休業・満枠等 |
| ⑮ | &more ボタン | タイムラインを週表示 → 月表示に切替 |

- 対応 API：`GET /reservations`（`date_from`/`date_to`/`staff_id`）、空き判定は `GET /availability`、編集は `PUT /reservations/{note_code}`（楽観ロック）。
- 予約可能 / 不可の算出は予約ロジック設計書 4「空き時間算出ロジック」に従う（営業時間 `t_business_hour`・休業 `t_holiday`・シフト `t_shift`）。
