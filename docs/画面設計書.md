# 画面設計書

> Be:note サロン予約管理システム / サロン用 Web 管理ツール

---

## 概要

本書はサロン用 Web 管理ツールの画面仕様を定義する。

- 旧 pptx『サロン用Web管理ツール_要件定義書兼UI設計書』（2022/2/5 初版）を下地に、再定義済みの各設計書（予約ロジック / DB / API）と整合する形で起こし直したものである。
- 対象は**店舗側（スタッフ・管理者）が使う Web 管理ツール**。顧客向けの画面はモバイルアプリ（React Native）で別途定義する。
- 画面と API・データの対応は本書では概要のみ示し、詳細は各設計書を正とする。

## 画面遷移

```
[ログイン]
    │ ログイン成功（staff 以上）
    ▼
[メニュー] ──┬───────────┬───────────┬──────────────┐
   │         │           │           │（admin のみ）  │
   ▼         ▼           ▼           ▼              ▼
[予約受付] [予約ボード] [予約管理]  [日報管理]      [材料管理]
   │ ▲ ▲     │ ▲         │ ▲       [マスタメンテ]
   │ │ └──────┘ │         │ │
   │ └──────────────────────┘
   ▼
[Be:note]  ← 予約受付 / 予約ボードの note 押下で遷移
```

- 予約受付・予約ボード・予約管理は相互に遷移できる（画面上部の `clerk` / `board` / `reserve` ボタン）。
- 各予約から `note` を押下すると当該顧客の Be:note へ遷移する。
- 管理者メニュー（日報管理・材料管理・マスタメンテ）は権限が admin のときのみメニューに表示される。

### Route Groups との対応（実装方針）

予約ロジック設計書「プロジェクト構成」の方針に従い、`web/` 配下を認証状態・ロールで分離する。

| Route Group | 対象画面 | 適用 |
|---|---|---|
| `(auth)` | ログイン | 未認証レイアウト |
| `(app)` | メニュー・予約受付・予約ボード・予約管理・Be:note | 共通ヘッダ付き・staff 以上 |
| `(admin)` | 日報管理・材料管理・マスタメンテ | admin ガード付き |

## 共通仕様

### 共通ヘッダ（全画面共通部）

ログイン後の全画面で共通して表示する。

| 要素 | 説明 |
|---|---|
| 画面名 | 現在の画面名称を表示 |
| 戻るボタン | 一つ前の画面に遷移 |
| ログイン情報 | ユーザー名・ログイン権限・アイコンを表示 |
| ログアウトボタン | ログイン画面へ遷移 |
| メッセージ表示部 | 通知・エラー等を表示（無ければ非表示） |
| リトライボタン | ページの再描画（再取得）を行う |

### 権限レベル

| ロール | ログイン | 表示範囲 |
|---|---|---|
| staff | 可 | メニュー〜Be:note |
| admin | 可 | 全画面（管理者メニュー含む） |
| customer | 本ツールでは不可（モバイルアプリ側） | Be:note は自分の分のみ参照可 |

- 本ツールのログインは**権限レベルがスタッフ以上**に限定する。
- 管理者メニュー（日報管理・材料管理・マスタメンテ）は**管理者以上**に限定して表示する。

### 顧客検索モーダル（check in）

予約受付・予約ボード・予約管理の `check in` ボタンから共通で呼び出す。

- 顧客を検索・選択し、来店処理（対象予約の `checked_in` 化、または新規 Be:note 作成）の起点とする。
- 詳細仕様は未確定（→ 末尾「未解決事項 / TODO」）。

## 各画面詳細

### ログイン（`/login`）✅

未認証ユーザーが管理ツールにログインする画面。

| 要素 | 説明 |
|---|---|
| タイトル | 「管理ツールログイン」 |
| アカウント ID | 認証方式を選択（下表） |
| ログインパスワード | Be:note 独自方式のときに使用 |

**認証方式**（予約ロジック設計書「ログイン方式」に準拠）

| フェーズ | 方式 | 備考 |
|---|---|---|
| 1 | Be:note 独自（メール＋パスワード） | パスワードリセット・メール認証が必要 |
| 1 | Google | OAuth2 |
| 1 | Instagram | Meta OAuth |
| 2 | LINE | 後回し |

- 認証は Supabase Auth が担い、ロール（`staff` / `admin`）は DB で管理する。
- **旧版との差分**：旧 pptx は LINE をフェーズ 1 に含めていたが、再定義で LINE はフェーズ 2 に後回しとした。
- 対応：Supabase Auth（API 設計書「認証」参照）。

### 予約受付（`/clerk`）✅

**当日の予約のみ**を一覧表示する受付画面。

| 要素 | 説明 |
|---|---|
| 現在日時 | 現在の日付・時刻 |
| board ボタン | 予約ボードへ遷移 |
| reserve ボタン | 予約管理へ遷移 |
| check in ボタン | 顧客検索モーダルを表示（共通仕様参照） |
| check out チェックボックス | 会計済み（`done`）の予約の表示制御（✓で表示） |
| 予約情報リスト領域 | 当日予約をリスト表示（下記項目） |
| note ボタン | 対象顧客の Be:note へ遷移 |
| Choice チェックボックス | 複数 Be:note を選択 → 複数会計 / 複数表示（※検討中） |

**リスト表示項目**：受付 No.（当日連番）／予約時間（開始）／顧客名（フリガナなし）／メニュー（主メニュー）／担当スタッフ（主担）／note

- 対応 API：`GET /reservations`（当日 = `date_from`/`date_to` 省略時）、Be:note 遷移は `GET /clients/{client_id}/notes`。
- **未確定**：複数 Be:note の同時表示は検討中（→ 末尾「未解決事項 / TODO」）。

### 予約ボード（`/board`）✅

**来店中の予約のみ**を、スタッフ × 作業タスクのボード形式で表示する。施術進捗をドラッグ＆ドロップで進める。

| 要素 | 説明 |
|---|---|
| 現在日時 | 現在の日付・時刻 |
| clerk ボタン | 予約受付へ遷移 |
| reserve ボタン | 予約管理へ遷移 |
| check in ボタン | 顧客検索モーダルを表示（共通仕様参照） |
| 予約ボード領域 | 列=スタッフ名、行=作業タスク。施術中の Be:note を配置 |
| スタイリスト行 | 全タスクを担当できる |
| アシスタント行 | 一部タスクに制限あり（`t_staff_skill` で設定） |
| Be:note カード | 予約単位のカード。顧客名／予約開始〜終了／メニュー／担当スタッフを表示 |
| done 領域 | 押下で done 済み Be:note を表示。選択して未 done に戻せる |

**作業タスクの流れ**（列方向の進行イメージ。実体は `t_task` 工程マスタ）：

```
check in → wash → cat → special wash → treatment → blow dry → After cat → finish → check out → done
```

- Be:note カードを左（check in）から右（check out）へドラッグ＆ドロップで進め、全タスク終了で `done` に移動（ボードから非表示）。
- ドロップ先の情報（進行タスク）は Be:note に自動移入。カード押下で Be:note へ遷移。
- 対応 API：`GET /reservations`（来店中 = `checked_in` / `in_progress`）、進行更新は `PATCH /reservations/{note_id}/task`。
- 状態との対応：`checked_in` → `in_progress`（`current_task_id` 進行）→ `done`（予約ロジック設計書「予約の状態遷移」）。

### 予約管理（`/reserve`）✅

予約をタイムライン表示し、予約の参照・編集を行う。staff リストボックスで表示モードを切り替える。

**表示モード**

| モード | 表示内容 |
|---|---|
| All（店舗表示） | 当日の予約のみ。列=スタッフ名、行=時間のタイムライン |
| スタッフ名（担当別表示） | 指定スタッフの予約を週 / 月単位でタイムライン表示 |

**画面要素（共通）**

| 要素 | 説明 |
|---|---|
| 現在日時 | 現在の日付・時刻 |
| clerk ボタン | 予約受付へ遷移 |
| board ボタン | 予約ボードへ遷移 |
| check in ボタン | 顧客検索モーダルを表示（共通仕様参照） |
| staff リストボックス | `All` / スタッフ名 を選択 |
| 予約管理領域 | 列=スタッフ名、行=時間。予約を開始〜終了時間で表示 |
| スタイリスト行 | 全タスクを担当できる |
| アシスタント行 | 一部タスクに制限あり（`t_staff_skill` で設定） |
| 予約可能領域 | 空き枠 |
| 予約不可領域 | 営業時間外・休業・既予約等 |
| 予約情報 | 顧客名（フリガナなし）／予約時間（開始〜終了）／メニュー（主）／主担 |

**担当別表示（staff＝スタッフ名）時の追加要素**

| 要素 | 説明 |
|---|---|
| スタッフ名 | 指定したスタッフ名を表示 |
| 予約可能日 | 空きのある日 |
| 予約不可日 | 休業・満枠等 |
| &more ボタン | タイムラインを週表示 → 月表示に切替 |

- 対応 API：`GET /reservations`（`date_from`/`date_to`/`staff_id`）、空き判定は `GET /availability`、編集は `PUT /reservations/{note_id}`（楽観ロック）。
- 予約可能 / 不可の算出は予約ロジック設計書「空き時間算出ロジック」に従う（営業時間 `t_business_hour`・休業 `t_holiday`・シフト `t_shift`）。

### Be:note（`/be_note/{client_id}`）✅

顧客カルテ本体。**1 顧客 = 1 つの Be:note**。来店ごとの `note` を時系列で管理し、カルテ参照・会計・店舗⇔顧客のやり取り（DM）を 1 画面に集約する。

- 本ツール（Web）は**店舗側ビュー**。顧客はモバイルアプリで**自分の Be:note のみ**参照する（権限差分は後述）。
- データ構造は来店ごとの `head` ノードを親に、`reservation` / `item` / `discount` / `photo` / `text` の子ノードがぶら下がる木構造（DB 設計書 `t_be_note` / `t_note_type`）。

**画面構成（レイアウト）**

```
┌───────────────────────────────────────────────┐
│ [共通ヘッダ] 画面名 / 戻る / ログイン情報 / ログアウト │
├───────────────────────────────────────────────┤
│ 顧客ヘッダ：顧客名 様（カナ）／性別・年齢・ランク      │
│            来店 n 回目        [▷ 詳細情報]         │
├──────────────────────────┬────────────────────┤
│ 来店 note（対象の 1 来店）   │ History_note         │
│  来店日時 / 担当 / status   │  過去の来店を         │
│  ・施術明細（menu）          │  新しい順に一覧        │
│  ・物販 / 割引 / 写真         │  （選択で左に表示）     │
│  total            [▷ 会計] │                      │
├──────────────────────────┴────────────────────┤
│ DM（交換ノート）：店舗⇔顧客のテキスト・画像           │
│ 予約情報参照：確定済みの未来予約                      │
└───────────────────────────────────────────────┘
```

**顧客ヘッダ**

| 要素 | 説明 | データ |
|---|---|---|
| 顧客名・カナ | 「顧客太郎 様（コキャクタロウ）」 | `t_client.client_name` / `client_kana` |
| 性別・年齢 | 年齢は `birthday` から算出 | `t_client.sex` / `birthday` |
| ランク・来店回数 | サロンごとの情報 | `t_client_salon.client_rank` / `total_visit` |
| 詳細情報ボタン | モーダルで全項目（住所・電話・髪質・アレルギー・職業・メモ）を表示 | `t_client` / `t_client_salon.memo` |

**来店 note 表示エリア**（対象 `head` ノード）

| 要素 | 説明 | データ |
|---|---|---|
| 来店日時 | 来店（親ノード作成）日時 | `t_be_note.creation_datetime` |
| 担当スタッフ | 主担当 | `t_be_note.responsible` → `t_staff` |
| status | 予約状態（`confirmed`〜`done` 等） | `t_reservation.status` |
| 明細領域 | note_type 別に表示（下表） | 子ノード各テーブル |
| total | 会計合計（税込） | `t_reservation.total` |
| 会計ボタン | 会計モーダルを開く（後述） | — |

**note_type 別の明細表示**

| note_type | 表示内容 | データ | 備考 |
|---|---|---|---|
| `reservation`（施術） | menu／staff／memo／price のリスト＋施術時間 | `t_menu` | **施術時間（`start_time`/`end_time`）は管理画面のみ表示**（顧客非表示） |
| `item`（物販） | 商品名／担当／memo／price | `t_sold_item` | |
| `discount`（割引） | 割引名／memo／price（負値） | `t_discount` | total から減算 |
| `photo`（写真） | ビフォー／アフター画像サムネイル | `t_photo` | `storage_path` を Supabase Storage の**署名付き URL** に変換して表示 |
| `text`（メッセージ） | DM エリアに表示（下記） | `t_be_note`（text 列） | |

**History_note エリア**

- 同一顧客の過去の来店（`head` ノード）を **`creation_datetime` 降順**で一覧表示する。
- 行を選択すると、その来店 note を左の表示エリアに展開する（旧版の「過去 note 参照」に相当）。
- 表示項目：来店日時／担当スタッフ／主メニュー／total。

**DM（交換ノート）エリア**

- `text` ノードを時系列のスレッドで表示する。`is_client` で**店舗発言（右）／顧客発言（左）**を振り分ける。
- テキスト＋画像（ヘアカタログ写真・アップロード画像）を送受信できる。
- 既読管理は `read_flg`。店舗側で顧客の未読メッセージにバッジ表示。
- 送信は `POST /clients/{client_id}/notes`（note_type=`text`）。リアルタイム同期は Supabase Realtime を想定（→ 未確定）。

**予約情報参照**

- `future_flg = true` の**確定済み未来予約**を表示する（旧版の「確定済みの未来の予約情報を参照」に相当）。

**会計フロー**

```
[▷ 会計] → 会計モーダル（明細確認・割引適用） → 支払方法を選択（cash / card / qr）
        → total 確定 → status を done に更新（actual_end を記録）
```

- 対応 API：`PATCH /reservations/{note_id}/status`（`done` へ）。明細編集は `POST /clients/{client_id}/notes`（item / discount 追加）。
- **複数会計**：予約受付の Choice チェックボックスで選択した複数 Be:note の一括会計は**検討中**（→ 末尾「未解決事項 / TODO」）。

**権限差分**

| ロール | 閲覧 | 編集・会計 | DM |
|---|---|---|---|
| staff / admin | 全項目（施術時間含む） | 可 | 送受信可 |
| customer（モバイル） | **自分の Be:note のみ**。施術時間など管理項目は非表示 | 不可（参照のみ） | 送受信可・来店後の感想記入 |

**対応 API**

- `GET /clients/{client_id}`：顧客情報＋サロン情報＋家族一覧
- `GET /clients/{client_id}/notes`：Be:note 一覧（`head` ＋子ノード）。`future_flg` で未来予約を絞り込み
- `GET /clients/{client_id}/notes/{note_id}`：note 詳細（note_type 別レスポンス）
- `POST /clients/{client_id}/notes`：note 作成（施術・物販・割引・写真・DM テキスト）

> **未確定事項**：(1) 複数会計の UI、(2) DM のリアルタイム同期方式（Supabase Realtime）、(3) 写真アップロード UI（ビフォー/アフターの紐付け）、(4) note 編集履歴（`note_version`）の表示要否。

### 日報管理（`/report`）✅

管理者権限。指定期間（既定は当日）の売上・客数・スタッフ別実績などを集計表示する。集計は会計済み（`status = 'done'`）の予約を対象とし、既存テーブルから算出する（新規テーブル不要）。

| 要素 | 説明 |
|---|---|
| 期間選択 | 日次（既定＝当日）／期間指定（`date_from`〜`date_to`） |
| サマリ | 売上合計・客数・客単価・キャンセル件数・no-show 件数 |
| 支払方法内訳 | `cash` / `card` / `qr` ごとの金額 |
| スタッフ別実績 | 担当スタッフごとの売上・施術件数 |
| メニュー別売上 | メニューごとの件数・売上 |
| エクスポート | CSV 出力（将来対応） |

- 対応 API：`GET /reports/daily`（`date_from`/`date_to`）。
- 集計元：`t_reservation`（`total` / `payment_method` / `staff_id` / `status`）、`t_menu`（スタッフ別・メニュー別）、`t_sold_item` / `t_discount`。

### 材料管理（`/material`）✅

管理者権限。材料の在庫照会・入出庫登録・低在庫アラートを行う。データは **材料マスタ（`t_material`）＋入出庫台帳（`t_material_transaction`）**（DB 設計書「材料系」）。

| 要素 | 説明 |
|---|---|
| 材料一覧 | 材料名／単位／現在庫／発注点。発注点割れは**低在庫アラート**表示 |
| 低在庫フィルタ | 発注点割れ（`current_stock <= reorder_point`）のみ表示 |
| 入庫登録 | 数量・メモを入力（`transaction_type = in`）。現在庫に加算 |
| 出庫登録 | 数量・メモを入力（`out`）。現在庫から減算 |
| 棚卸調整 | 実数との差分を反映（`adjust`） |
| 入出庫履歴 | 材料ごとの履歴（日時・種別・数量・操作者・メモ） |
| 材料マスタ登録 | 新規材料の追加（材料名・単位・発注点） |

- 対応 API：`GET /materials`（`low_stock_only`）、`POST /materials`、`GET /materials/{material_id}/transactions`、`POST /materials/{material_id}/transactions`。
- `current_stock` は台帳から更新するキャッシュ。入出庫登録時にサーバ側で更新する。
- **将来拡張**：施術メニューごとの材料消費量（BOM）連携。MVP は手動の入出庫登録とする。

### マスタメンテ（`/master`）✅

管理者権限。各種マスタの保守（CRUD）を集約する画面。

**画面構成（レイアウト）**

```
┌───────────────────────────────────────────────┐
│ [共通ヘッダ]                                       │
├───────────────┬───────────────────────────────┤
│ マスタ選択       │ 選択マスタの一覧      [＋ 新規追加]  │
│  ・メニュー       │ ┌─────────────────────────┐ │
│  ・工程          │ │ 行（クリックで編集モーダル）      │ │
│  ・スタッフ       │ │ ...                         │ │
│  ・可能タスク     │ │ [編集] [削除]                │ │
│  ・営業時間       │ └─────────────────────────┘ │
│  ・休業          │                               │
│  ・シフト         │                               │
│  ・予約枠         │                               │
│  ・材料          │                               │
└───────────────┴───────────────────────────────┘
```

**共通操作**

| 要素 | 説明 |
|---|---|
| マスタ選択 | 左メニューで保守対象マスタを切り替え |
| 一覧 | 選択マスタのレコードを一覧表示（`delete_flg=false` のみ） |
| 新規追加 | 編集モーダルを空で開く → `POST /masters/{resource}` |
| 編集 | 行クリックで編集モーダル → `PUT /masters/{resource}/{id}` |
| 削除 | 論理削除（`delete_flg=true`）→ `DELETE /masters/{resource}/{id}` |

**保守対象マスタと主な編集項目**

| マスタ | resource | 主な編集項目 | 特記 |
|---|---|---|---|
| メニュー | `menus` | menu_name / kinds / base_price / duration_minutes | |
| 工程 | `tasks` | task_name / task_order / role_limit | `task_order` で予約ボードの列順が変わる |
| スタッフ | `staff` | staff_name / staff_kana / position / is_admin / nomination_fee | position＝stylist/assistant、is_admin＝管理者権限 |
| 可能タスク | `staff-skills` | スタッフ×タスクの**マトリクス**（チェックで付与/剥奪） | 複合キー。`POST`＝付与 / `DELETE`＝剥奪 |
| 営業時間 | `business-hours` | 曜日別 open_time / close_time | 曜日（0=日〜6=土）単位 |
| 休業 | `holidays` | holiday_date / reason | カレンダーで指定 |
| シフト | `shifts` | staff_id / shift_date / start_time / end_time | 件数が多い。将来は専用「シフト管理」画面に分離余地 |
| 予約枠 | `slots` | slot_name | |
| 材料 | `materials` | material_name / unit / reorder_point | 在庫の入出庫は**材料管理画面**で行う（本画面はマスタ項目のみ） |

**バリデーション（共通方針）**

- 必須項目の未入力、価格・所要時間・発注点の負値、時刻の前後関係（open < close、start < end）をチェック。
- 参照されているレコードの削除は論理削除のみ（物理削除しない）。

- 対応 API：`GET/POST/PUT/DELETE /masters/{resource}`（API 設計書「マスタ保守（CRUD）」）。
