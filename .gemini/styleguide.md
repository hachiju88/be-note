# レビュー方針（Be:note 設計リポジトリ）

このリポジトリは現状、`docs/` 配下の設計書（Markdown）が中心です。コードよりも**設計の一貫性**を重視してレビューしてください。

## 重点的に見てほしい点

1. **文書間の整合性**
   - `予約ロジック設計書.md` / `DB設計書.md` / `API設計書.md` / `画面設計書.md` の間で、テーブル名・カラム名・エンドポイント・状態名（status）・note_type が一致しているか。
   - 片方だけ更新されて他方とズレている箇所がないか。

2. **データモデルの妥当性**
   - 主キーは全テーブル UUID（`t_note_type` のみ `SMALLINT`）。新規テーブルもこの方針に従っているか。
   - 外部キー・参照整合性、論理削除（`delete_flg`）の一貫性。
   - 権限は `t_staff.is_admin`、職位は `t_staff.position`（混同しない）。

3. **API 設計**
   - パスの一貫性（予約リソースは `{note_id}` で識別）。
   - 認証・ロール（customer / staff / admin）と各エンドポイントの権限が妥当か。
   - 冪等キー・楽観ロック（`version_no`）の扱い。

4. **参照の健全性**
   - 文書間参照は見出し名ベース。壊れた参照・存在しない見出しへの参照がないか。

5. **Markdown 品質**
   - 表・コードフェンス・見出し階層の崩れ。

## トーン

- 設計上の実害がある不整合を優先。表記ゆれなど軽微な指摘は重大度を下げる。
- 日本語でコメントしてください。
